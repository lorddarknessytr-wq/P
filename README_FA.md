# قالب پروکسی Gemini برای مخزن‌های TLP

این پوشه یک **قالب یکسان** برای هر یک از چهار مخزن پروکسی است. محتوای همین پوشه را در ریشهٔ هر چهار مخزن قرار بده؛ مسیر `P/` را داخل خود مخزن نساز.

## فایل‌های لازم در هر مخزن

```text
.github/workflows/proxy.yml
worker.py
requirements.txt
requests/.gitkeep
responses/.gitkeep
```

نام فایل Workflow باید دقیقاً `proxy.yml` و شاخه مطابق کانفیگ Ranflare (پیش‌فرض `main`) باشد.

## روش کار

ربات اصلی روی Ranflare اجرا می‌شود. زمان‌بند آن معمولاً هر ۳۵۵ دقیقه (۵ ساعت و ۵۵ دقیقه) مخزن بعدی را فعال می‌کند تا با سقف شش‌ساعتهٔ GitHub Actions فاصلهٔ امن داشته باشد. Ranflare درخواست را به مسیر `requests/<id>.json` مخزن فعال می‌نویسد. این Worker آن را می‌خواند، با کلید Gemini که داخل درخواست آمده به API گوگل وصل می‌شود و پاسخ را در `responses/<id>.json` ذخیره می‌کند.

**این Worker خودش را دوباره Dispatch نمی‌کند.** اجرای بعدی و لغو اجرای قبلی فقط توسط زمان‌بند موجود در Ranflare انجام می‌شود. به این ترتیب چهار مخزن به‌صورت نوبتی فعال می‌شوند و Workerهای قدیمی روی مخزن‌های دیگر باقی نمی‌مانند.

## تنظیمات GitHub Actions

در هر مخزن Actions باید فعال باشد. Workflow دارای `permissions: contents: write` است تا `GITHUB_TOKEN` خودکار بتواند فایل پاسخ را بنویسد و درخواست پردازش‌شده را حذف کند. PAT اصلی در GitHub Secrets قرار نمی‌گیرد؛ آن را فقط در `config.json` خصوصی Ranflare قرار بده.

## نکتهٔ امنیتی

نسخهٔ فعلی پروتکل کلید Gemini را به صورت Base64 در فایل درخواست می‌گذارد. Base64 رمزنگاری نیست. هر چهار مخزن باید Private باشند و فقط حساب‌های مورد اعتماد به آن‌ها دسترسی داشته باشند. حذف فایل صف از آخرین commit، نسخهٔ آن را از تاریخچهٔ قبلی Git پاک نمی‌کند. کلیدهای قبلی که در مخزن عمومی یا در اختیار فرد غیرمجاز بوده‌اند باید تعویض شوند.

`proxy.py` و `tunnel.py` در این بسته به‌عنوان فایل‌های قدیمی حفظ شده‌اند؛ ارتباط صفی ربات Ranflare با `worker.py` و `.github/workflows/proxy.yml` انجام می‌شود.
